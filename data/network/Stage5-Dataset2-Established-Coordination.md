# Stage 5, Dataset 2 — Established Coordination Network

**Purpose.** Every relationship below is one for which the frozen Episode records code M as **established** — never plausible, emerging, suspected, inferred, or based only on shared participation, institutional access, co-chairing, or endorsement/co-signature. No edge here was inferred from repeated co-participation; where two actors appear together often but M was not independently established, no edge was created (see the companion Validation Table for every candidate considered and rejected). No `edge_weight` has been added; no relationship type or coordination-level scale beyond what is documented below is introduced into the canonical `Edges.md` schema. This is a separate, derived analytical dataset.

**Modelling note (read before using this dataset — also stated in the Validation Memo).** "Actor-to-actor" is interpreted literally only where the underlying evidence documents a genuinely dyadic relationship (exactly two named actors). Three categories of established M exist across the four Episodes that are **not** dyadic, and forcing them into a two-actor shape would misstate what is actually documented:

1. **Multi-actor (3+) relational configurations** where the evidence documents each actor's joint contribution to one shared, named process, but does not document specific bilateral exchange content between every possible pair (e.g., the New Delhi Science Working Group's three co-chairs; the AISI Network's Joint Testing Exercises; GPAI's Expert Working Groups). These are represented as **actor → MECHANISM/COALITION-node edges** (a hub structure), using the Codebook §24 node types already authorised (STATE, COALITION, MECHANISM, INSTRUMENT) — not as a complete graph of every pairwise combination, which would overstate the evidence.
2. **Unilateral institutional-entrepreneurship acts** where exactly one state is named as constructing, expanding, or chairing an institution (Japan's Friends Group creation; Canada's and Japan's GPAI founding role; India's GPAI chairmanship/institutional-integration act). These have no second named state to form a dyad with. They are represented as **actor → COALITION/INSTRUMENT-node edges**, not actor-to-actor (state-to-state) edges, and are listed in a separate table (2B) so they are never mistaken for a relational tie between two states.
3. **Genuinely dyadic (exactly 2 named actors) relationships** — Singapore–Japan (Bletchley); Japan–India (Hiroshima) — are represented as ordinary **STATE-to-STATE** edges (Table 2A).

This distinction is not a schema change: COALITION, MECHANISM, and INSTRUMENT are already-authorised Codebook §24 node types. It is a representational choice, made explicit here and in the Validation Memo, to avoid inventing pairwise ties the evidence does not document and to avoid silently dropping genuinely established M findings that do not happen to be dyadic. No canonical ID convention exists yet in Codebook §25 for COALITION/MECHANISM/INSTRUMENT nodes (only COUNTRY, SOURCE, EVIDENCE, EPISODE, CLAIM, and MEMO have a defined ID format) — these nodes are therefore referenced below by the same descriptive name already used in the frozen Episode and in `03-Episodes/Stage4-Cross-Case-Matrix.md`, not by an invented ID prefix. This is flagged as an ontology limitation in the Validation Memo, not resolved unilaterally here.

**Cross-episode relationship tracking (added 2026-09-07, researcher-authorised).** `Stage5-Network-Analysis-Memo.md` notes that two raw observations below — the Singapore–Japan observation (Table 2A) and Singapore's AISI Network Joint Testing Exercises observation (Table 2B) — are both grounded in the same underlying activity: the frozen Bletchley Episode record itself describes the Singapore–Japan joint testing exercise as conducted "under the AISI network," and `EP-AISI-NETWORK-2024.md` independently identifies this as the Network's own "second exercise (Feb. 2025, Singapore–Japan)." These two raw observations are therefore treated as a **possible duplicate** — provisionally linked, neither deleted nor merged — via a shared `underlying_relationship_id` and a `possible_cross_episode_duplicate` flag, added as two new columns to Tables 2A and 2B below. Both raw observations, and all other rows, are otherwise left completely unchanged — no evidence, episode attribution, coordination level, or status is altered by this tagging, and no row is deleted or merged. The purpose is solely to let downstream network-level counts (e.g., "how many distinct underlying relationships does Singapore hold") avoid double-counting one underlying relationship as two, while preserving both raw observations exactly as documented so the tagging can be revisited if future evidence shows the two activities were genuinely distinct. This is a separate question from whether the Singapore–Japan raw observation is itself well-corroborated: on that question, the Bletchley-era evidence is Singapore's own Research Note, and the AISI Network's later record of the same activity is cross-Episode corroboration of it (`corroboration_scope = cross_episode`), not same-Episode corroboration by Japan, whose own Bletchley country-attribution record remains silent throughout (see that row's Note, above). Neither the possible-duplicate tagging nor the cross-Episode corroboration changes Japan's own M coding: Japan's Bletchley "plausible, not established" finding is unaffected, since observed shared activity under one relationship ID is not, by itself, grounds to upgrade a country-attribution finding (see the corresponding note in `Coding-Decisions-Log.md`).
